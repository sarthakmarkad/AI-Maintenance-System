## Reproduction

No ffmpeg executable or Pillow was initially installed. A small ignored tooling environment was created at `.local/landing-video-tools` with Pillow 13.0.0 and imageio-ffmpeg 0.6.0 (bundled ffmpeg 7.1). No app dependencies/lockfile were changed. To recreate tooling, use Python venv and install these two pinned packages there; run `.local/landing-video-tools/bin/python scripts/landing-video/render.py`. The renderer uses macOS Arial fonts by default; `LANDING_VIDEO_FONT` / `LANDING_VIDEO_BOLD_FONT` can supply existing equivalent TTF paths elsewhere. It makes no model/network/app/database calls. It writes the public export/poster/metadata plus six ignored `.local/landing-video-scene-*.jpg` review stills. Keep export completion before copying assets into a fixture app.

Run `node scripts/landing-video/verify.mjs` from the repository root. It writes an ignored temporary Playwright configuration under `.local`, and uses the documented fixture-copy approach from the RCA browser workflow: only app/components/lib/public and package/build config are copied into `.local/landing-video-web`; no .env, credentials or company reference files. Its Next cache and port **3123** are separate from 3000, 3100 and 4000. Supabase/API URLs are the existing intercepted browser-fixture URLs. `reuseExistingServer:false` protects other servers. Shared app configuration is untouched.
